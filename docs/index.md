## 📚 Welcome to Docs as Code

This documentation is powered by **Docs as Code** - a modern approach to documentation that treats documentation with the same care and practices we use for source code.

### What is Docs as Code?

Docs as Code means:
- **Documentation lives alongside your code** in the same repository
- **Version controlled** - every change is tracked and can be rolled back
- **Collaborative** - use pull requests, code reviews, and team workflows
- **Automated** - documentation is built and deployed automatically
- **Consistent** - same tools, same processes, same quality standards

### Why Docs as Code Matters

✅ **Always Up-to-Date**: Documentation changes with code changes in the same PR  
✅ **Developer Friendly**: Write in Markdown, the language developers already know  
✅ **Searchable**: Integrated with Backstage's global search  
✅ **Consistent**: Standardized format across all projects  
✅ **Collaborative**: Easy for anyone to contribute and improve  
✅ **Automated**: Builds and deploys automatically on every commit  

### Getting Started

1. **Edit documentation**: Modify the `.md` files in the `/docs` folder
2. **Use Markdown**: Simple, powerful formatting that developers love
3. **Preview locally**: Run MkDocs locally to see changes before committing
4. **Commit changes**: Documentation updates automatically when you push to the repository

### Customizing Your Documentation

This template provides you with a starting structure, but you have complete freedom to customize it:

- **Replace this page**: You can completely overwrite this `index.md` with your project-specific content
- **Add new pages**: Create additional `.md` files for different topics (we've included `second-page.md` as an example)
- **Organize content**: Structure your documentation however makes sense for your project
- **Use MkDocs features**: Add navigation, themes, plugins, and more advanced features

### Best Practices

- Keep documentation close to the code it describes
- Update docs in the same PR as code changes
- Use clear, descriptive headings and structure
- Include code examples and diagrams when helpful
- Review documentation changes just like code changes
